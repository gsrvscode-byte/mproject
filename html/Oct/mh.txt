**3. REST API**
"REST is an architectural style where resources are exposed through URLs and accessed with HTTP methods: GET reads, POST creates, PUT/PATCH update, DELETE removes. It's stateless, so each request carries everything needed, usually in JSON, and uses proper status codes (200, 201, 400, 401, 404, 500)."

**4. Microservices**
"The application is split into small services, each owning one business capability and often its own database. They deploy and scale independently and communicate via REST or message queues like RabbitMQ. The benefit is scalability and fault isolation. The trade-off is more complexity in monitoring, data consistency and deployment."

**5. Why Node.js**
"Node runs on a single-threaded, event-driven, non-blocking I/O model, so it handles many concurrent connections efficiently. It's great for I/O-heavy work like APIs and integrations. For CPU-heavy tasks I'd use worker threads or a separate service."

**6. Express.js**
"A minimal Node framework for routing, middleware and error handling. Middleware is the key idea: each request passes through functions like auth, validation and logging before reaching the controller."

**7. async/await**
"It's syntax built on Promises that makes async code read like synchronous code. I use try/catch for errors, and `Promise.all` when independent calls can run in parallel."

**8. Error handling**
"I use a centralized error middleware in Express, custom error classes with status codes, request validation (Joi/Zod), and a wrapper for async handlers. I also handle unhandled rejections, log with a tool like Winston, and never leak stack traces to clients."

**9. NGINX**
"A reverse proxy and web server. I've used it for routing to backend services, load balancing, SSL termination and serving static files."

**10–11. npm and nvm**
"npm manages packages via package.json, and package-lock.json locks exact versions. nvm switches between Node versions, which is useful when projects need different ones."

**12–13. Docker and Kubernetes**
"Docker packages an app with its dependencies into a container so it runs the same everywhere. Kubernetes orchestrates many containers: deployment, auto-scaling, load balancing, rolling updates and self-healing. Docker builds and runs containers, and Kubernetes manages them at scale."

**14. CI/CD**
"CI automatically builds and tests code on every push or PR. CD deploys it automatically. In my project I used [Jenkins/GitHub Actions]: on merge it runs tests, builds a Docker image and deploys to [server/AWS]."

**15. Azure** (honest)

**16–17. Databases, MongoDB vs PostgreSQL**
"MongoDB stores flexible JSON-like documents and suits fast-changing schemas. PostgreSQL stores structured relational data with joins and ACID transactions, so it suits things like payments. I choose based on data structure and consistency needs."

**18. API performance**
"I measure first, using logs and monitoring to find the bottleneck. Then I fix it: add DB indexes, optimize queries, use pagination, cache with Redis, avoid N+1 queries, run independent calls in parallel, and move heavy work to queues. Then I benchmark again."

**19. API security**
"JWT or session authentication, RBAC, bcrypt password hashing, input validation, HTTPS, Helmet for secure headers, rate limiting, CORS configuration and protection against injection. Secrets stay in environment variables."
