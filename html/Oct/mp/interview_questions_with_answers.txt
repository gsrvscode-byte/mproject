Q1. What is Node.js? / Node.js kya hai?
EN: Node.js is an open-source, cross-platform JavaScript runtime built on Chrome's V8 engine. It lets you run JavaScript outside the browser, mainly for server-side apps. It is event-driven and uses non-blocking I/O, which makes it lightweight and efficient for I/O-heavy applications like APIs and real-time apps.
HI: Node.js ek open-source, cross-platform JavaScript runtime hai jo Chrome ke V8 engine par bana hai. Isse hum JavaScript ko browser ke bahar (server par) run kar sakte hain. Ye event-driven aur non-blocking I/O use karta hai, isliye APIs aur real-time apps jaise I/O-heavy applications ke liye bahut efficient hai.


Q2. How does the Node.js event loop work? / Node.js ka event loop kaise kaam karta hai?
EN: Node.js runs JavaScript on a single thread. The event loop continuously checks for pending work and runs callbacks. Heavy I/O work (file, network, DB) is handed to libuv / the OS / a thread pool, and when it finishes, its callback is queued. The loop has phases: timers (setTimeout/setInterval) -> pending callbacks -> poll (I/O events) -> check (setImmediate) -> close callbacks. Between phases, process.nextTick and Promise microtasks run first.
HI: Node.js JavaScript ko single thread par run karta hai. Event loop continuously check karta rehta hai ki koi pending kaam ya callback hai ya nahi. Heavy I/O kaam (file, network, DB) libuv / OS / thread pool ko de diya jata hai, aur kaam khatam hone par uska callback queue mein aa jata hai. Phases: timers -> pending callbacks -> poll (I/O) -> check (setImmediate) -> close callbacks. Har phase ke beech mein pehle process.nextTick aur Promise microtasks chalte hain.


Q3. What is asynchronous programming in Node.js? / Node.js mein asynchronous programming kya hoti hai?
EN: In asynchronous programming, a long-running task (like a DB query or HTTP call) does not block the rest of the code. Node starts the task, continues executing other code, and handles the result later via a callback, Promise, or async/await. This allows one thread to serve thousands of requests.
HI: Asynchronous programming mein koi lamba chalne wala task (jaise DB query ya HTTP call) baaki code ko block nahi karta. Node task start karke aage ka code chalata rehta hai, aur result baad mein callback, Promise ya async/await se handle hota hai. Isse ek hi thread hazaron requests serve kar pata hai.


Q4. Difference between callbacks, Promises, and async/await? / Callbacks, Promises aur async/await mein difference?
EN:
- Callback: a function passed to another function, called when work is done. Many nested callbacks cause "callback hell" and messy error handling.
- Promise: an object representing a future result (pending/fulfilled/rejected). Supports chaining with .then() / .catch().
- async/await: syntax sugar over Promises that makes async code look synchronous and lets you use try/catch. It is the cleanest and most readable approach.
HI:
- Callback: ek function jo dusre function ko pass hota hai aur kaam khatam hone par call hota hai. Zyada nesting se "callback hell" ban jata hai aur error handling mushkil hoti hai.
- Promise: ek object jo future ke result ko represent karta hai (pending/fulfilled/rejected). .then() / .catch() se chaining hoti hai.
- async/await: Promises ke upar syntax sugar hai jisse async code synchronous jaisa dikhta hai aur try/catch use kar sakte hain. Ye sabse clean aur readable tarika hai.


Q5. What is middleware in Express.js? / Express.js mein middleware kya hota hai?
EN: Middleware is a function with access to (req, res, next) that runs between the incoming request and the final route handler. It can modify req/res, end the request, or call next() to pass control on. Used for logging, authentication, body parsing, CORS, validation, and error handling. Error-handling middleware has 4 arguments: (err, req, res, next).
HI: Middleware ek function hai jisko (req, res, next) milte hain aur ye request aur final route handler ke beech mein chalta hai. Ye req/res modify kar sakta hai, request ko end kar sakta hai, ya next() call karke aage bhej sakta hai. Logging, authentication, body parsing, CORS, validation aur error handling mein use hota hai. Error-handling middleware mein 4 arguments hote hain: (err, req, res, next).


Q6. How do you handle errors in Node.js? / Node.js mein errors kaise handle karte ho?
EN:
- Use try/catch with async/await, and .catch() with Promises.
- Error-first callbacks: callback(err, data).
- In Express, use a centralized error-handling middleware.
- Create custom error classes (e.g., AppError with statusCode).
- Listen to process.on('unhandledRejection') and process.on('uncaughtException') for logging and graceful shutdown.
- Log errors (Winston/Pino) and never expose stack traces in production.
HI:
- async/await ke saath try/catch, aur Promises ke saath .catch() use karte hain.
- Error-first callbacks: callback(err, data).
- Express mein ek centralized error-handling middleware banate hain.
- Custom error classes banate hain (jaise AppError with statusCode).
- process.on('unhandledRejection') aur process.on('uncaughtException') se logging aur graceful shutdown karte hain.
- Errors ko log karte hain (Winston/Pino) aur production mein stack trace user ko nahi dikhate.


Q7. How do you improve Node.js API performance? / Node.js API ki performance kaise improve karte ho?
EN:
- Avoid blocking the event loop; use async code.
- Cache with Redis / in-memory.
- Add DB indexes, optimize queries, use connection pooling, and use pagination.
- Use clustering / PM2 / load balancer to use all CPU cores.
- Enable gzip/brotli compression.
- Use streams for large data.
- Move heavy tasks to queues/workers.
- Profile with clinic.js / APM tools and fix bottlenecks.
HI:
- Event loop ko block mat karo; async code use karo.
- Redis / in-memory caching use karo.
- DB indexes lagao, queries optimize karo, connection pooling aur pagination use karo.
- Clustering / PM2 / load balancer se saare CPU cores use karo.
- gzip/brotli compression enable karo.
- Bade data ke liye streams use karo.
- Heavy kaam queues/workers ko do.
- clinic.js / APM tools se profiling karke bottlenecks fix karo.


Q8. What is clustering in Node.js? / Node.js mein clustering kya hoti hai?
EN: Node runs on a single thread/core by default. The built-in cluster module forks multiple worker processes (usually one per CPU core) that all share the same server port, and the master distributes incoming connections. This improves throughput and availability. PM2's cluster mode (pm2 start app.js -i max) does this easily.
HI: Node by default ek hi thread/core par chalta hai. Built-in cluster module multiple worker processes (aam taur par har CPU core ke liye ek) fork karta hai jo same port share karte hain, aur master incoming connections ko distribute karta hai. Isse throughput aur availability badhti hai. PM2 ka cluster mode (pm2 start app.js -i max) ye aasani se kar deta hai.


Q9. What are streams in Node.js? / Node.js mein streams kya hote hain?
EN: Streams let you process data in small chunks instead of loading everything in memory. Four types: Readable, Writable, Duplex (both), and Transform (modify data while passing, e.g., gzip). You connect them with .pipe() or pipeline(). They handle backpressure and are ideal for large files, video, and network data.
HI: Streams se hum data ko chhote-chhote chunks mein process karte hain, poora data memory mein load nahi karna padta. 4 types: Readable, Writable, Duplex (dono), aur Transform (data ko beech mein modify karna, jaise gzip). Inhe .pipe() ya pipeline() se jodte hain. Ye backpressure handle karte hain aur bade files, video aur network data ke liye best hain.


Q10. How do you handle CPU-intensive tasks in Node.js? / CPU-intensive tasks kaise handle karte ho?
EN: CPU-heavy code blocks the single thread. Solutions: (1) worker_threads for parallel computation, (2) child_process / cluster, (3) offload to a job queue (Bull/RabbitMQ) with separate workers, (4) move it to a separate microservice or a language better suited for it, (5) break the work into small chunks using setImmediate.
HI: CPU-heavy code single thread ko block kar deta hai. Solutions: (1) parallel computation ke liye worker_threads, (2) child_process / cluster, (3) job queue (Bull/RabbitMQ) ke saath alag workers, (4) alag microservice ya kisi better language mein shift karna, (5) kaam ko setImmediate se chhote chunks mein todna.

Q11. What is TypeScript and why do we use it? / TypeScript kya hai aur kyun use karte hain?
EN: TypeScript is a superset of JavaScript that adds static typing and compiles to plain JavaScript. We use it to catch bugs at compile time, get better IDE autocomplete and refactoring, make code self-documenting, and maintain large codebases more safely.
HI: TypeScript JavaScript ka superset hai jo static typing add karta hai aur compile hokar plain JavaScript ban jata hai. Hum ise isliye use karte hain taaki bugs compile time par hi pakad lein, IDE mein better autocomplete aur refactoring mile, code self-documenting ho, aur bade codebase ko safely maintain kar sakein.


Q12. Difference between interface and type? / Interface aur type mein difference?
EN:
- interface: mainly for object shapes/classes; can be extended (extends) and supports declaration merging (same name declared twice merges).
- type: can alias anything - primitives, unions, tuples, mapped/conditional types; extended using intersection (&); no declaration merging.
Rule of thumb: use interface for object contracts/public APIs, type for unions and complex types.
HI:
- interface: mainly object shapes/classes ke liye; extends se extend hota hai aur declaration merging support karta hai (same naam do baar likhne par merge ho jata hai).
- type: kuch bhi alias kar sakta hai - primitives, unions, tuples, mapped/conditional types; intersection (&) se extend hota hai; declaration merging nahi hoti.
Thumb rule: object contracts ke liye interface, unions aur complex types ke liye type.


Q13. What are generics in TypeScript? / Generics kya hote hain?
EN: Generics let you write reusable code that works with many types while staying type-safe, using type parameters like <T>.
Example: function identity<T>(value: T): T { return value; }
identity<string>("hi") returns a string; identity<number>(5) returns a number. Used in API response wrappers, arrays (Array<T>), Promise<T>, etc.
HI: Generics se hum aisa reusable code likh sakte hain jo alag-alag types ke saath kaam kare aur type-safe bhi rahe, <T> jaise type parameters ke zariye.
Example: function identity<T>(value: T): T { return value; }
identity<string>("hi") string return karega; identity<number>(5) number. API response wrappers, Array<T>, Promise<T> waghera mein use hota hai.


Q14. Difference between any, unknown, and never? / any, unknown aur never mein difference?
EN:
- any: turns off type checking; anything is allowed (unsafe).
- unknown: type-safe version of any; you can assign anything but must narrow (typeof/instanceof) before using it.
- never: a value that never occurs - function that always throws or has an infinite loop; also used for exhaustive checks in switch statements.
HI:
- any: type checking band kar deta hai; kuch bhi allowed hai (unsafe).
- unknown: any ka type-safe version; kuch bhi assign kar sakte ho lekin use karne se pehle narrow (typeof/instanceof) karna padta hai.
- never: aisi value jo kabhi aati hi nahi - jo function hamesha throw kare ya infinite loop ho; switch mein exhaustive check ke liye bhi use hota hai.


Q15. What are union and intersection types? / Union aur intersection types kya hote hain?
EN:
- Union (A | B): value can be either type. Example: let id: string | number;
- Intersection (A & B): value must satisfy both types combined. Example: type Admin = User & { permissions: string[] };
HI:
- Union (A | B): value dono mein se koi ek type ki ho sakti hai. Example: let id: string | number;
- Intersection (A & B): value ko dono types ki saari properties satisfy karni hongi. Example: type Admin = User & { permissions: string[] };


Q16. What is type narrowing? / Type narrowing kya hoti hai?
EN: Narrowing is when TypeScript refines a broad type to a more specific one inside a code block. Techniques: typeof, instanceof, the "in" operator, equality checks, truthiness checks, discriminated unions (a common 'type' field), and custom type guards (function isDog(x): x is Dog).
HI: Narrowing mein TypeScript kisi broad type ko code block ke andar specific type mein badal deta hai. Techniques: typeof, instanceof, "in" operator, equality checks, truthiness checks, discriminated unions (common 'type' field), aur custom type guards (function isDog(x): x is Dog).


Q17. What are access modifiers in TypeScript? / Access modifiers kya hote hain?
EN:
- public (default): accessible everywhere.
- private: accessible only inside the class.
- protected: accessible inside the class and its subclasses.
- readonly: can be set only once (at declaration or in constructor).
HI:
- public (default): har jagah accessible.
- private: sirf class ke andar accessible.
- protected: class aur uski subclasses ke andar accessible.
- readonly: sirf ek baar set ho sakta hai (declaration ya constructor mein).


Q18. How do you type an Express API request and response? / Express request aur response ko kaise type karte ho?
EN: Import types from express and pass generics: Request<Params, ResBody, ReqBody, Query>.
  import { Request, Response, NextFunction } from 'express';
  interface CreateUserBody { name: string; email: string; }
  app.post('/users', (req: Request<{}, {}, CreateUserBody>, res: Response, next: NextFunction) => {
    const { name, email } = req.body; // typed
    res.status(201).json({ name, email });
  });
Also install @types/express and @types/node, and use Zod/Joi for runtime validation since TypeScript types disappear at runtime.
HI: express se types import karo aur generics pass karo: Request<Params, ResBody, ReqBody, Query>.
  (upar wala code example dekhiye)
@types/express aur @types/node install karo, aur runtime validation ke liye Zod/Joi use karo kyunki TypeScript types runtime par exist nahi karte.

Q19. What is REST API? / REST API kya hoti hai?
EN: REST (Representational State Transfer) is an architectural style for building web services over HTTP. Resources are identified by URLs (e.g., /users/1) and manipulated using HTTP methods (GET, POST, PUT, PATCH, DELETE). Key principles: stateless, client-server, uniform interface, cacheable, layered system. Data is usually exchanged as JSON.
HI: REST (Representational State Transfer) HTTP par web services banane ka ek architectural style hai. Resources URLs se identify hote hain (jaise /users/1) aur HTTP methods (GET, POST, PUT, PATCH, DELETE) se manipulate hote hain. Key principles: stateless, client-server, uniform interface, cacheable, layered system. Data aam taur par JSON mein exchange hota hai.


Q20. Difference between PUT and PATCH? / PUT aur PATCH mein difference?
EN:
- PUT: replaces the entire resource; you send the full object. It is idempotent.
- PATCH: partially updates only the fields you send. Usually idempotent but not guaranteed.
Example: to change just a user's email, use PATCH /users/1 with { "email": "new@x.com" }.
HI:
- PUT: poore resource ko replace karta hai; full object bhejna padta hai. Ye idempotent hai.
- PATCH: sirf bheje gaye fields ko partially update karta hai. Aam taur par idempotent hota hai par guarantee nahi.
Example: sirf email badalna ho to PATCH /users/1 with { "email": "new@x.com" }.


Q21. What are HTTP status codes? / HTTP status codes kya hote hain?
EN: Three-digit codes the server returns to describe the result:
- 1xx: informational
- 2xx: success - 200 OK, 201 Created, 204 No Content
- 3xx: redirection - 301 Moved Permanently, 304 Not Modified
- 4xx: client error - 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 422 Unprocessable Entity, 429 Too Many Requests
- 5xx: server error - 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout
HI: Server ye 3-digit codes return karta hai request ka result batane ke liye:
- 1xx: informational
- 2xx: success - 200 OK, 201 Created, 204 No Content
- 3xx: redirection - 301 Moved Permanently, 304 Not Modified
- 4xx: client error - 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 422 Unprocessable Entity, 429 Too Many Requests
- 5xx: server error - 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout


Q22. How do you design a scalable REST API? / Scalable REST API kaise design karte ho?
EN:
- Keep it stateless so any instance can serve any request.
- Use clear resource naming (nouns, plural) and API versioning (/v1/).
- Add pagination, filtering, and sorting.
- Cache responses (Redis, HTTP cache headers, CDN).
- Add rate limiting and compression.
- Optimize DB: indexes, read replicas, connection pooling.
- Run behind a load balancer with horizontal scaling.
- Use queues for slow/background work.
- Add monitoring and logging.
HI:
- API ko stateless rakho taaki koi bhi instance koi bhi request serve kar sake.
- Clear resource naming (nouns, plural) aur API versioning (/v1/) use karo.
- Pagination, filtering aur sorting add karo.
- Responses cache karo (Redis, HTTP cache headers, CDN).
- Rate limiting aur compression lagao.
- DB optimize karo: indexes, read replicas, connection pooling.
- Load balancer ke peeche horizontal scaling karo.
- Slow/background kaam ke liye queues use karo.
- Monitoring aur logging add karo.


Q23. How do you implement authentication and authorization? / Authentication aur authorization kaise implement karte ho?
EN:
- Authentication = who are you (login). Verify credentials (hash passwords with bcrypt), then issue a JWT/session. OAuth2/SSO for third-party login.
- Authorization = what are you allowed to do. Implement RBAC/permissions via middleware that checks the user's role/claims before the route runs.
Flow: login -> server verifies -> returns access token (+ refresh token) -> client sends "Authorization: Bearer <token>" -> auth middleware verifies token and attaches user to req -> role middleware checks permission.
HI:
- Authentication = aap kaun ho (login). Credentials verify karo (passwords bcrypt se hash karo), phir JWT/session issue karo. Third-party login ke liye OAuth2/SSO.
- Authorization = aap kya kar sakte ho. RBAC/permissions middleware se implement karte hain jo route chalne se pehle user ka role/claims check karta hai.
Flow: login -> server verify karta hai -> access token (+ refresh token) deta hai -> client "Authorization: Bearer <token>" bhejta hai -> auth middleware token verify karke user ko req mein attach karta hai -> role middleware permission check karta hai.


Q24. What is JWT? / JWT kya hota hai?
EN: JWT (JSON Web Token) is a compact, signed token used to securely transmit claims between client and server. It has 3 parts: header.payload.signature (base64url encoded). The server signs it with a secret/private key, so it can verify it without storing sessions (stateless). Best practices: short-lived access tokens + refresh tokens, HTTPS only, never put sensitive data in the payload (it is encoded, not encrypted).
HI: JWT (JSON Web Token) ek compact, signed token hai jo client aur server ke beech claims securely bhejne ke liye use hota hai. Isme 3 parts hote hain: header.payload.signature (base64url encoded). Server ise secret/private key se sign karta hai, isliye bina session store kiye verify kar sakta hai (stateless). Best practices: short-lived access token + refresh token, sirf HTTPS, payload mein sensitive data kabhi mat daalo (ye encoded hota hai, encrypted nahi).


Q25. How do you implement API validation? / API validation kaise implement karte ho?
EN: Validate all incoming data (body, params, query, headers) before processing, using libraries like Joi, Zod, class-validator, or express-validator. Put validation in a middleware, return 400/422 with clear error messages, sanitize input to prevent injection, and validate on the server even if the frontend validates too.
HI: Processing se pehle saara incoming data (body, params, query, headers) validate karo, Joi, Zod, class-validator ya express-validator jaisi libraries se. Validation ko middleware mein rakho, clear error messages ke saath 400/422 return karo, injection rokne ke liye input sanitize karo, aur frontend validation hone ke baad bhi server par validate zaroor karo.


Q26. How do you handle API errors? / API errors kaise handle karte ho?
EN: Use a centralized error-handling middleware, custom error classes, correct HTTP status codes, and a consistent response format such as { "success": false, "code": "USER_NOT_FOUND", "message": "User not found" }. Log the full error internally (with request ID), but hide stack traces and internal details from clients in production. Handle async errors with try/catch or a wrapper.
HI: Centralized error-handling middleware, custom error classes, sahi HTTP status codes aur ek consistent response format use karo jaise { "success": false, "code": "USER_NOT_FOUND", "message": "User not found" }. Full error ko internally log karo (request ID ke saath), lekin production mein stack trace aur internal details client ko mat dikhao. Async errors ko try/catch ya wrapper se handle karo.


Q27. How do you implement pagination? / Pagination kaise implement karte ho?
EN:
- Offset/limit: GET /users?page=2&limit=10 -> skip=(page-1)*limit. Simple but slow on huge tables.
- Cursor-based: GET /users?cursor=<lastId>&limit=10 -> uses the last item's id/timestamp. Faster and stable for large/real-time data.
Return metadata: total, page, limit, nextCursor/hasNext. Always set a max limit.
HI:
- Offset/limit: GET /users?page=2&limit=10 -> skip=(page-1)*limit. Simple hai par bade tables par slow.
- Cursor-based: GET /users?cursor=<lastId>&limit=10 -> last item ka id/timestamp use hota hai. Bade/real-time data ke liye fast aur stable.
Metadata return karo: total, page, limit, nextCursor/hasNext. Hamesha ek max limit set karo.

Q29. What are microservices? / Microservices kya hoti hain?
EN: Microservices is an architecture where an application is split into small, independent services, each handling one business capability (e.g., user, order, payment). Each service has its own codebase and usually its own database, is deployed independently, and communicates over APIs or messages.
HI: Microservices ek architecture hai jisme application ko chhoti, independent services mein baanta jata hai, har service ek business capability handle karti hai (jaise user, order, payment). Har service ka apna codebase aur aam taur par apna database hota hai, independently deploy hoti hai, aur APIs ya messages se communicate karti hai.


Q30. Monolithic vs microservices architecture? / Monolithic aur microservices mein difference?
EN:
- Monolith: one single codebase and deployable unit. Simple to build, test, and deploy initially, but hard to scale parts independently, and a small change needs full redeploy; one bug can bring everything down.
- Microservices: many small services. Independent deploy/scale and fault isolation, but more complexity (networking, monitoring, data consistency).
Start with a monolith for small apps; move to microservices when scale/team size demands it.
HI:
- Monolith: ek hi codebase aur ek hi deployable unit. Shuru mein build, test, deploy karna aasan, lekin parts ko alag scale nahi kar sakte, chhote change ke liye bhi poora redeploy, aur ek bug se sab down ho sakta hai.
- Microservices: bahut saari chhoti services. Independent deploy/scale aur fault isolation, lekin complexity zyada (networking, monitoring, data consistency).
Chhote apps ke liye monolith se start karo; scale/team size badhne par microservices mein jao.


Q31. Advantages and disadvantages of microservices? / Microservices ke advantages aur disadvantages?
EN:
Advantages: independent deployment, scale only what is needed, technology flexibility, fault isolation, smaller codebases, faster team autonomy.
Disadvantages: operational complexity, network latency and failures, distributed transactions and data consistency, harder debugging/testing, need for DevOps maturity (CI/CD, monitoring, tracing), higher infrastructure cost.
HI:
Advantages: independent deployment, sirf zaroori service ko scale karna, technology flexibility, fault isolation, chhote codebases, teams ki autonomy.
Disadvantages: operational complexity, network latency aur failures, distributed transactions aur data consistency, debugging/testing mushkil, DevOps maturity chahiye (CI/CD, monitoring, tracing), infra cost zyada.


Q32. How do microservices communicate with each other? / Microservices ek dusre se kaise communicate karti hain?
EN:
- Synchronous: REST over HTTP, gRPC, GraphQL (request-response, caller waits).
- Asynchronous: message brokers/event streaming like RabbitMQ, Kafka, SQS (publish/subscribe or queues; services are loosely coupled).
Often both are used: sync for queries, async for events/background tasks.
HI:
- Synchronous: HTTP par REST, gRPC, GraphQL (request-response, caller wait karta hai).
- Asynchronous: RabbitMQ, Kafka, SQS jaise message brokers/event streaming (publish/subscribe ya queues; services loosely coupled rehti hain).
Aksar dono use hote hain: queries ke liye sync, events/background tasks ke liye async.


Q33. REST vs RabbitMQ for service communication? / Service communication ke liye REST vs RabbitMQ?
EN:
- REST: synchronous, simple, easy to debug, immediate response. But services are tightly coupled; if the target is down the call fails, and the caller waits.
- RabbitMQ: asynchronous message broker. Loose coupling, messages are buffered/retried if a consumer is down, supports pub/sub and work queues, good for spikes and background jobs. But adds infrastructure, eventual consistency, and harder debugging.
Use REST when you need an immediate answer; use RabbitMQ for events, long tasks, and decoupling.
HI:
- REST: synchronous, simple, debug karna aasan, turant response. Lekin services tightly coupled hoti hain; target down ho to call fail ho jaata hai aur caller wait karta hai.
- RabbitMQ: asynchronous message broker. Loose coupling, consumer down ho to messages buffer/retry hote hain, pub/sub aur work queues support, spikes aur background jobs ke liye acha. Lekin infra badhta hai, eventual consistency aur debugging mushkil.
Turant answer chahiye to REST; events, lambe tasks aur decoupling ke liye RabbitMQ.


Q34. What is an API Gateway? / API Gateway kya hota hai?
EN: An API Gateway is a single entry point for all client requests to the backend microservices. It handles routing, authentication, rate limiting, load balancing, request/response transformation, caching, SSL termination, and logging, and can aggregate responses from multiple services. Examples: Kong, AWS API Gateway, NGINX, Apigee.
HI: API Gateway backend microservices tak jaane wali saari client requests ka ek single entry point hota hai. Ye routing, authentication, rate limiting, load balancing, request/response transformation, caching, SSL termination aur logging handle karta hai, aur multiple services ke responses ko combine bhi kar sakta hai. Examples: Kong, AWS API Gateway, NGINX, Apigee.


Q35. How do you handle failures between microservices? / Microservices ke beech failures kaise handle karte ho?
EN:
- Timeouts so calls don't hang forever
- Retries with exponential backoff (and jitter)
- Circuit breaker (stop calling a failing service; e.g., opossum library)
- Fallbacks / graceful degradation
- Bulkhead pattern (isolate resources)
- Idempotent operations so retries are safe
- Message queues with dead-letter queues
- Health checks, monitoring, alerts, distributed tracing
HI:
- Timeouts taaki calls hamesha hang na rahein
- Exponential backoff (aur jitter) ke saath retries
- Circuit breaker (fail ho rahi service ko call karna band kar do; jaise opossum library)
- Fallbacks / graceful degradation
- Bulkhead pattern (resources isolate karo)
- Idempotent operations taaki retry safe ho
- Dead-letter queues ke saath message queues
- Health checks, monitoring, alerts, distributed tracing


Q36. What is service discovery? / Service discovery kya hoti hai?
EN: In dynamic environments, service instances start, stop, and change IPs constantly. Service discovery lets services find each other automatically using a registry. Client-side: the client queries a registry (Consul, Eureka) and picks an instance. Server-side: a load balancer/router does the lookup. In Kubernetes, built-in DNS and Services provide discovery (e.g., http://order-service).
HI: Dynamic environments mein service instances start, stop hote rehte hain aur unke IP badalte rehte hain. Service discovery se services ek registry ke zariye ek dusre ko automatically dhoondh leti hain. Client-side: client registry (Consul, Eureka) se poochta hai aur instance chunta hai. Server-side: load balancer/router lookup karta hai. Kubernetes mein built-in DNS aur Services discovery dete hain (jaise http://order-service).


Q37. How do you handle transactions across multiple microservices? / Multiple microservices ke across transactions kaise handle karte ho?
EN: Traditional ACID/2-phase commit does not scale well across services. Use the Saga pattern: a sequence of local transactions, each publishing an event/triggering the next; if one step fails, compensating transactions undo previous steps. Two styles: choreography (services react to events) and orchestration (a central orchestrator coordinates). Also use the Outbox pattern for reliable event publishing, idempotent consumers, and accept eventual consistency.
HI: Traditional ACID/2-phase commit services ke across achha scale nahi karta. Saga pattern use karte hain: local transactions ki sequence, har step event publish karta hai ya agla step trigger karta hai; koi step fail ho to compensating transactions pichhle steps ko undo kar deti hain. Do styles: choreography (services events par react karti hain) aur orchestration (ek central orchestrator coordinate karta hai). Saath mein reliable event publishing ke liye Outbox pattern, idempotent consumers, aur eventual consistency accept karna.


Q38. How would you design a scalable microservices application? / Scalable microservices application kaise design karoge?
EN:
1. Split services by business domain (DDD): user, product, order, payment.
2. Database per service.
3. API Gateway as the single entry point (auth, rate limiting).
4. Sync (REST/gRPC) for queries; async (RabbitMQ/Kafka) for events.
5. Containerize with Docker; orchestrate with Kubernetes for auto-scaling and self-healing.
6. Caching (Redis), CDN, DB replicas.
7. Resilience: circuit breakers, retries, timeouts.
8. Centralized logging, metrics, tracing (ELK, Prometheus, Grafana, Jaeger).
9. CI/CD per service.
10. Security: service-to-service auth, secrets management.
HI:
1. Business domain ke hisaab se services baanto (DDD): user, product, order, payment.
2. Har service ka apna database.
3. API Gateway single entry point (auth, rate limiting).
4. Queries ke liye sync (REST/gRPC); events ke liye async (RabbitMQ/Kafka).
5. Docker se containerize karo; auto-scaling aur self-healing ke liye Kubernetes.
6. Caching (Redis), CDN, DB replicas.
7. Resilience: circuit breakers, retries, timeouts.
8. Centralized logging, metrics, tracing (ELK, Prometheus, Grafana, Jaeger).
9. Har service ka alag CI/CD.
10. Security: service-to-service auth, secrets management.

Q39. What is Docker? / Docker kya hai?
EN: Docker is a containerization platform that packages an application with all its dependencies (runtime, libraries, config) into a lightweight, portable container. It runs the same way on any machine, solving the "works on my machine" problem. Containers share the host OS kernel, so they are lighter and faster than virtual machines.
HI: Docker ek containerization platform hai jo application ko uski saari dependencies (runtime, libraries, config) ke saath ek lightweight, portable container mein package karta hai. Ye har machine par same tarah chalta hai, "mere machine par to chal raha tha" problem solve karta hai. Containers host OS ka kernel share karte hain, isliye virtual machines se halke aur fast hote hain.


Q40. Docker image vs container? / Docker image aur container mein difference?
EN:
- Image: a read-only template/blueprint containing the app, dependencies, and instructions (built from a Dockerfile).
- Container: a running instance of an image, with its own writable layer, process, and network.
Analogy: image = class, container = object. One image can create many containers.
HI:
- Image: read-only template/blueprint jisme app, dependencies aur instructions hote hain (Dockerfile se banta hai).
- Container: image ka running instance, jiska apna writable layer, process aur network hota hai.
Analogy: image = class, container = object. Ek image se kai containers ban sakte hain.


Q41. What is a Dockerfile? / Dockerfile kya hoti hai?
EN: A Dockerfile is a text file with step-by-step instructions (FROM, WORKDIR, COPY, RUN, ENV, EXPOSE, CMD/ENTRYPOINT) that Docker uses to build an image. Each instruction creates a cached layer.
HI: Dockerfile ek text file hai jisme step-by-step instructions (FROM, WORKDIR, COPY, RUN, ENV, EXPOSE, CMD/ENTRYPOINT) hote hain jinse Docker image build karta hai. Har instruction ek cached layer banata hai.


Q42. Explain a typical Node.js Dockerfile. / Ek typical Node.js Dockerfile explain kijiye.
EN:
  FROM node:20-alpine          # small base image with Node
  WORKDIR /app                 # working directory inside container
  COPY package*.json ./        # copy only package files first (layer caching)
  RUN npm ci --omit=dev        # install production dependencies
  COPY . .                     # copy the rest of the source code
  ENV NODE_ENV=production      # set environment variable
  EXPOSE 3000                  # document the app port
  CMD ["node", "dist/index.js"] # command to start the app
Tips: copy package.json before source so dependency layer is cached; use a .dockerignore (node_modules, .git); use multi-stage build for TypeScript (build stage compiles, final stage has only dist + prod deps); run as non-root user.
HI: Upar wali Dockerfile dekhiye. Step by step: node:20-alpine chhota base image hai; WORKDIR container ke andar working folder set karta hai; pehle sirf package.json copy karte hain taaki dependency layer cache ho jaye; npm ci --omit=dev se production dependencies install hoti hain; phir baaki source code copy hota hai; ENV se environment variable set; EXPOSE port document karta hai; CMD app start karne ki command hai.
Tips: .dockerignore use karo (node_modules, .git); TypeScript ke liye multi-stage build (build stage compile kare, final stage mein sirf dist + prod deps ho); non-root user se run karo.


Q43. What is Docker Compose? / Docker Compose kya hai?
EN: Docker Compose is a tool to define and run multi-container applications using a single docker-compose.yml file (services, ports, volumes, networks, env vars). One command - docker compose up - starts everything, e.g., Node app + MongoDB + Redis. Great for local development and testing.
HI: Docker Compose multi-container applications ko ek hi docker-compose.yml file se define aur run karne ka tool hai (services, ports, volumes, networks, env vars). Ek command - docker compose up - se sab kuch start ho jata hai, jaise Node app + MongoDB + Redis. Local development aur testing ke liye bahut useful.


Q44. How do you pass environment variables to Docker? / Docker mein environment variables kaise pass karte ho?
EN:
- docker run -e KEY=value image
- docker run --env-file .env image
- ENV KEY=value in the Dockerfile (for non-secret defaults)
- In Compose: "environment:" or "env_file:" sections
- For sensitive values: Docker secrets, Kubernetes Secrets, or a cloud secret manager - never bake secrets into the image.
HI:
- docker run -e KEY=value image
- docker run --env-file .env image
- Dockerfile mein ENV KEY=value (non-secret defaults ke liye)
- Compose mein "environment:" ya "env_file:" section
- Sensitive values ke liye: Docker secrets, Kubernetes Secrets ya cloud secret manager - secrets ko kabhi image mein bake mat karo.


Q45. How do you reduce Docker image size? / Docker image ka size kaise kam karte ho?

- Multi-stage builds (leave build tools behind)
- Install only production dependencies (npm ci --omit=dev)
- Use .dockerignore
- Combine RUN commands and clean caches (npm cache clean --force)

Q46. How do you debug a Docker container? / Docker container ko debug kaise karte ho?

- docker logs -f <container>: view logs
- docker exec -it <container> sh: open a shell inside
- docker inspect <container>: config, env, network, mounts
- docker stats: CPU/memory usage
- docker events and checking resource limits/ports

Q47. How do you deploy a Dockerized Node.js application? / Dockerized Node.js application kaise deploy karte ho?

6. KUBERNETES
---------------------------------------------------------------------

Q48. What is Kubernetes? / Kubernetes kya hai?
EN: Kubernetes (K8s) is an open-source container orchestration platform that automates deploying, scaling, load balancing, self-healing, and updating containerized applications across a cluster of machines.
HI: Kubernetes (K8s) ek open-source container orchestration platform hai jo machines ke cluster par containerized applications ko deploy, scale, load balance, self-heal aur update karne ko automate karta hai.


Q49. What is a Pod? / Pod kya hota hai?
EN: A Pod is the smallest deployable unit in Kubernetes. It wraps one or more tightly coupled containers that share the same network (IP/ports) and storage volumes. Pods are ephemeral - if one dies, a new one is created with a different IP.
HI: Pod Kubernetes ki sabse chhoti deployable unit hai. Ye ek ya zyada tightly coupled containers ko wrap karta hai jo same network (IP/ports) aur storage volumes share karte hain. Pods ephemeral hote hain - ek mar jaye to naya pod alag IP ke saath ban jata hai.


Q50. What is a Deployment? / Deployment kya hota hai?
EN: A Deployment is a Kubernetes object that declaratively manages a set of identical Pods through ReplicaSets. You specify the desired number of replicas and the image; it ensures that state, supports rolling updates with zero downtime, and rollbacks (kubectl rollout undo).
HI: Deployment ek Kubernetes object hai jo ReplicaSets ke zariye identical Pods ke set ko declaratively manage karta hai. Aap replicas ki desired sankhya aur image batate ho; ye wahi state maintain karta hai, zero downtime rolling updates aur rollbacks (kubectl rollout undo) support karta hai.


Q51. What is a Kubernetes Service? / Kubernetes Service kya hoti hai?
EN: A Service gives a stable IP/DNS name and load balances traffic across a set of Pods (selected by labels), since Pod IPs keep changing. Types: ClusterIP (internal only, default), NodePort (exposes on each node's port), LoadBalancer (cloud load balancer), ExternalName. An Ingress is often used on top for HTTP routing.
HI: Service ek stable IP/DNS naam deti hai aur labels se select kiye gaye Pods ke beech traffic load balance karti hai, kyunki Pod IPs badalte rehte hain. Types: ClusterIP (sirf internal, default), NodePort (har node ke port par expose), LoadBalancer (cloud load balancer), ExternalName. HTTP routing ke liye aksar upar Ingress use hota hai.


Q52. What is ConfigMap? / ConfigMap kya hota hai?
EN: A ConfigMap stores non-sensitive configuration as key-value pairs (e.g., API URLs, log level). Pods consume it as environment variables or mounted files, so configuration is separated from the container image and can change without rebuilding.
HI: ConfigMap non-sensitive configuration ko key-value pairs mein store karta hai (jaise API URLs, log level). Pods ise environment variables ya mounted files ke roop mein use karte hain, isliye configuration image se alag rehta hai aur bina rebuild kiye badal sakta hai.


Q53. What is Secret? / Secret kya hota hai?
EN: A Secret stores sensitive data such as passwords, API keys, and tokens. Like ConfigMap it can be exposed as env vars or files. Note: values are only base64-encoded by default, not encrypted - so enable encryption at rest, restrict access with RBAC, or use external secret managers (Vault, AWS Secrets Manager).
HI: Secret passwords, API keys, tokens jaisa sensitive data store karta hai. ConfigMap ki tarah ise env vars ya files ke roop mein de sakte hain. Dhyan rahe: values default mein sirf base64-encoded hoti hain, encrypted nahi - isliye encryption at rest enable karo, RBAC se access restrict karo, ya external secret managers (Vault, AWS Secrets Manager) use karo.


Q54. How does Kubernetes scale an application? / Kubernetes application ko scale kaise karta hai?
EN:
- Manual: kubectl scale deployment myapp --replicas=5
- Horizontal Pod Autoscaler (HPA): automatically adds/removes Pods based on CPU/memory or custom metrics
- Vertical Pod Autoscaler (VPA): adjusts CPU/memory requests of Pods
- Cluster Autoscaler: adds/removes worker nodes when Pods can't be scheduled
Requires resource requests/limits to be defined.
HI:
- Manual: kubectl scale deployment myapp --replicas=5
- Horizontal Pod Autoscaler (HPA): CPU/memory ya custom metrics ke basis par Pods automatically add/remove karta hai
- Vertical Pod Autoscaler (VPA): Pods ki CPU/memory requests adjust karta hai
- Cluster Autoscaler: Pods schedule na ho paane par worker nodes add/remove karta hai
Iske liye resource requests/limits define hone chahiye.


Q55. Difference between Deployment and Service? / Deployment aur Service mein difference?
EN:
- Deployment: manages the Pods' lifecycle - how many replicas, which image, rolling updates, rollbacks, self-healing.
- Service: provides stable networking - a fixed IP/DNS and load balancing to those Pods.
They work together: the Deployment runs the Pods; the Service exposes them.
HI:
- Deployment: Pods ka lifecycle manage karta hai - kitne replicas, kaunsi image, rolling updates, rollbacks, self-healing.
- Service: stable networking deti hai - fixed IP/DNS aur un Pods tak load balancing.
Dono saath kaam karte hain: Deployment Pods chalata hai; Service unhe expose karti hai.


Q56. How would you deploy a Node.js application on Kubernetes? / Node.js application ko Kubernetes par kaise deploy karoge?
EN:
1. Dockerize the app and push the image to a registry (ECR/Docker Hub).
2. Write deployment.yaml (replicas, image, port, env from ConfigMap/Secret, resource requests/limits, readiness and liveness probes).
3. Write service.yaml (ClusterIP/LoadBalancer) and optionally an Ingress for domain/SSL.
4. Apply: kubectl apply -f deployment.yaml -f service.yaml
5. Verify: kubectl get pods,svc ; kubectl logs <pod>
6. Add HPA for autoscaling; use rolling updates for new versions (kubectl set image / rollout status) and rollout undo if needed.
7. Automate via CI/CD (or Helm / ArgoCD).
HI:
1. App ko Dockerize karo aur image registry (ECR/Docker Hub) par push karo.
2. deployment.yaml likho (replicas, image, port, ConfigMap/Secret se env, resource requests/limits, readiness aur liveness probes).
3. service.yaml likho (ClusterIP/LoadBalancer) aur domain/SSL ke liye optional Ingress.
4. Apply karo: kubectl apply -f deployment.yaml -f service.yaml
5. Verify karo: kubectl get pods,svc ; kubectl logs <pod>
6. Autoscaling ke liye HPA lagao; naye versions ke liye rolling update (kubectl set image / rollout status) aur zaroorat par rollout undo.
7. CI/CD (ya Helm / ArgoCD) se automate karo.

7. WEBPACK / VITE / BABEL
---------------------------------------------------------------------

Q57. What is Webpack? / Webpack kya hai?
EN: Webpack is a module bundler that takes your JavaScript modules (and assets like CSS, images) starting from an entry point, builds a dependency graph, and outputs optimized bundles. It uses loaders (transform files, e.g., babel-loader, ts-loader, css-loader) and plugins (extra tasks like minification, HTML generation) configured in webpack.config.js.
HI: Webpack ek module bundler hai jo entry point se shuru karke aapke JavaScript modules (aur CSS, images jaise assets) ka dependency graph banata hai aur optimized bundles output karta hai. Ye loaders (files transform karte hain, jaise babel-loader, ts-loader, css-loader) aur plugins (minification, HTML generation jaise extra kaam) use karta hai, jo webpack.config.js mein configure hote hain.


Q58. What is Vite? / Vite kya hai?
EN: Vite is a modern, fast frontend build tool. In development it serves source code over native ES modules and pre-bundles dependencies with esbuild, so the dev server starts almost instantly with very fast Hot Module Replacement (HMR). For production it bundles with Rollup. It works out of the box with TypeScript, JSX, and CSS.
HI: Vite ek modern, fast frontend build tool hai. Development mein ye source code ko native ES modules se serve karta hai aur dependencies ko esbuild se pre-bundle karta hai, isliye dev server lagbhag turant start hota hai aur HMR bahut fast hota hai. Production ke liye Rollup se bundle karta hai. TypeScript, JSX aur CSS ke saath out of the box kaam karta hai.


Q59. Webpack vs Vite? / Webpack aur Vite mein difference?
EN:
- Dev startup: Webpack bundles everything before serving (slower on big apps); Vite serves via native ESM (very fast).
- HMR: Vite is faster.
- Config: Vite is simpler with good defaults; Webpack is more complex but highly configurable.
- Production build: Webpack uses its own bundler; Vite uses Rollup.
- Ecosystem: Webpack has a larger, older plugin ecosystem and handles complex legacy setups (e.g., module federation); Vite is the modern default for new projects.
HI:
- Dev startup: Webpack serve karne se pehle sab bundle karta hai (bade apps mein slow); Vite native ESM se serve karta hai (bahut fast).
- HMR: Vite fast hai.
- Config: Vite simple hai aur achhe defaults deta hai; Webpack complex lekin highly configurable.
- Production build: Webpack apna bundler use karta hai; Vite Rollup use karta hai.
- Ecosystem: Webpack ka plugin ecosystem bada aur purana hai aur complex legacy setups (jaise module federation) handle karta hai; Vite naye projects ke liye modern default hai.


Q60. What is Babel? / Babel kya hai?
EN: Babel is a JavaScript compiler/transpiler that converts modern JavaScript (ES6+, JSX, TypeScript via preset) into backward-compatible JavaScript that older browsers/Node versions can run. It works through presets (e.g., @babel/preset-env, preset-react) and plugins, and can add polyfills.
HI: Babel ek JavaScript compiler/transpiler hai jo modern JavaScript (ES6+, JSX, preset ke zariye TypeScript) ko backward-compatible JavaScript mein convert karta hai jo purane browsers/Node versions chala sakein. Ye presets (jaise @babel/preset-env, preset-react) aur plugins se kaam karta hai aur polyfills bhi add kar sakta hai.


Q61. Why do we need a bundler? / Bundler ki zaroorat kyun padti hai?
EN: A bundler combines many modules into a few optimized files so the browser makes fewer requests; resolves imports/dependencies (including npm packages); transpiles modern syntax (Babel/TS); minifies and tree-shakes code; handles assets (CSS, images, fonts); enables code splitting, hashing for caching, and dev features like HMR.
HI: Bundler kai modules ko kuch optimized files mein combine karta hai taaki browser kam requests kare; imports/dependencies (npm packages samet) resolve karta hai; modern syntax ko transpile karta hai (Babel/TS); code ko minify aur tree-shake karta hai; assets (CSS, images, fonts) handle karta hai; code splitting, caching ke liye hashing, aur HMR jaise dev features deta hai.


Q62. What is tree shaking? / Tree shaking kya hoti hai?
EN: Tree shaking is a build optimization that removes unused (dead) code from the final bundle. It relies on static ES module syntax (import/export), so the bundler can see which exports are never used. Tips: use ES modules, avoid side effects (set "sideEffects": false in package.json), and import only what you need (import { debounce } from 'lodash-es').
HI: Tree shaking ek build optimization hai jo final bundle se unused (dead) code hata deti hai. Ye static ES module syntax (import/export) par depend karti hai, jisse bundler ko pata chal jata hai ki kaunse exports kabhi use nahi hue. Tips: ES modules use karo, side effects avoid karo (package.json mein "sideEffects": false), aur sirf zaroori cheez import karo (import { debounce } from 'lodash-es').


Q63. What is code splitting? / Code splitting kya hoti hai?
EN: Code splitting divides the bundle into smaller chunks that are loaded on demand instead of one huge file, improving initial load time. Done with dynamic import() (e.g., const Page = import('./Page')), React.lazy + Suspense for route-based splitting, and bundler config (vendor chunks, splitChunks in Webpack).
HI: Code splitting bundle ko chhote chunks mein baant deti hai jo ek bade file ki jagah zaroorat padne par load hote hain, isse initial load time improve hota hai. Dynamic import() (jaise const Page = import('./Page')), route-based splitting ke liye React.lazy + Suspense, aur bundler config (vendor chunks, Webpack mein splitChunks) se hota hai.


Q64. How do you optimize a frontend build? / Frontend build ko kaise optimize karte ho?
EN:
- Minify JS/CSS/HTML
- Tree shaking and removing unused dependencies
- Code splitting and lazy loading routes/components
- Compress assets (gzip/brotli), optimize images (WebP, lazy load)
- Content-hashed filenames for long-term caching; serve via CDN
- Analyze bundle size (webpack-bundle-analyzer / rollup-plugin-visualizer)
- Use production mode, source maps only as needed
- Use persistent caching and faster tools (esbuild/SWC/Vite) to speed up the build itself
HI:
- JS/CSS/HTML minify karo
- Tree shaking aur unused dependencies hatao
- Code splitting aur routes/components ka lazy loading
- Assets compress karo (gzip/brotli), images optimize karo (WebP, lazy load)
- Long-term caching ke liye content-hashed filenames; CDN se serve karo
- Bundle size analyze karo (webpack-bundle-analyzer / rollup-plugin-visualizer)
- Production mode use karo, source maps sirf zaroorat par
- Build ko tez karne ke liye persistent caching aur fast tools (esbuild/SWC/Vite) use karo

8. CI/CD & DEPLOYMENT

Q65. What is CI/CD? / CI/CD kya hota hai?
EN:
- CI (Continuous Integration): developers merge code frequently, and every commit automatically triggers build, lint, and tests to catch problems early.
- CD (Continuous Delivery): every passing build is automatically prepared for release; production deploy needs a manual approval.
- CD (Continuous Deployment): every passing build is deployed to production automatically.
Benefits: faster releases, fewer bugs, repeatable deployments.
HI:
- CI (Continuous Integration): developers frequently code merge karte hain, aur har commit par build, lint aur tests automatically chalte hain taaki problems jaldi pakdi jayein.
- CD (Continuous Delivery): har passing build automatically release ke liye ready hota hai; production deploy ke liye manual approval chahiye.
- CD (Continuous Deployment): har passing build automatically production par deploy ho jata hai.
Fayde: fast releases, kam bugs, repeatable deployments.


Q66. Explain your deployment process. / Apna deployment process explain kijiye.

Q76. What is Scrum? / Scrum kya hota hai?

Q81. How do you troubleshoot a slow API? / Slow API ko kaise troubleshoot karte ho?

4. Fix: add indexes/optimize queries, cache (Redis), paginate, parallelize with Promise.all, move heavy work to queues/workers, add timeouts, scale horizontally.
5. Re-measure and add monitoring/alerts.

4. Check infrastructure: CPU, memory (OOM kills), disk space, container/pod restarts (kubectl describe pod).
5. Check env variables/secrets/expired certificates or tokens.

Q83. How do you investigate high CPU usage? / High CPU usage ki investigation kaise karte ho?
EN: Confirm with top/htop/docker stats which process is using CPU. For Node.js, take a CPU profile (node --prof, node --inspect with Chrome DevTools, or clinic.js flamegraph/0x) to find hot functions. Common causes: synchronous loops, heavy JSON parse/stringify, regex backtracking, crypto/hashing on the main thread, large sorting, infinite loops, too many requests. Fixes: worker threads, caching, optimize algorithm, rate limiting, horizontal scaling.
HI: top/htop/docker stats se confirm karo kaunsa process CPU use kar raha hai. Node.js ke liye CPU profile lo (node --prof, Chrome DevTools ke saath node --inspect, ya clinic.js flamegraph/0x) taaki hot functions mil jayein. Common causes: synchronous loops, heavy JSON parse/stringify, regex backtracking, main thread par crypto/hashing, bada sorting, infinite loops, bahut zyada requests. Fixes: worker threads, caching, algorithm optimize, rate limiting, horizontal scaling.


Q84. How do you investigate high memory usage? / High memory usage ki investigation kaise karte ho?
EN: Monitor process.memoryUsage() and metrics to see if memory grows steadily (leak) or spikes. Take heap snapshots (node --inspect + Chrome DevTools, heapdump) at different times and compare to find retained objects. Common leak causes: global variables/unbounded caches, event listeners not removed, timers/intervals not cleared, closures holding references, large buffers/streams not consumed. Fixes: bounded/LRU caches, clean up listeners/timers, use streams, set --max-old-space-size and container memory limits, fix leaks, and restart policies as a safety net.
HI: process.memoryUsage() aur metrics se dekho ki memory dheere-dheere badh rahi hai (leak) ya achanak spike hua. Alag-alag time par heap snapshots lo (node --inspect + Chrome DevTools, heapdump) aur compare karke retained objects dhoondho. Common leak causes: global variables/unbounded caches, event listeners remove na karna, timers/intervals clear na karna, closures jo references pakde rahte hain, bade buffers/streams consume na hona. Fixes: bounded/LRU caches, listeners/timers cleanup, streams use karo, --max-old-space-size aur container memory limits set karo, leaks fix karo, aur safety net ke roop mein restart policies.


Q85. How do you troubleshoot a database query taking too long? / Slow database query ko kaise troubleshoot karte ho?
EN:
1. Identify the slow query (slow query log, APM, pg_stat_statements).
2. Run EXPLAIN / EXPLAIN ANALYZE to see the execution plan (full table scan? bad join?).
3. Add or fix indexes (composite indexes matching WHERE/ORDER BY), avoid functions on indexed columns.
4. Avoid SELECT *, N+1 queries; fetch only needed columns; add pagination/limits.
5. Optimize joins/subqueries; update statistics.
6. Check locks, connection pool, and server resources.
7. Cache results (Redis), use read replicas, partitioning, or denormalization when appropriate.
HI:
1. Slow query pehchano (slow query log, APM, pg_stat_statements).
2. EXPLAIN / EXPLAIN ANALYZE chalakar execution plan dekho (full table scan? kharab join?).
3. Indexes add/fix karo (WHERE/ORDER BY se match karte composite indexes), indexed columns par functions avoid karo.
4. SELECT *, N+1 queries avoid karo; sirf zaroori columns fetch karo; pagination/limits lagao.
5. Joins/subqueries optimize karo; statistics update karo.
6. Locks, connection pool aur server resources check karo.

Q86. How do you handle a production issue? / Production issue ko kaise handle karte ho?

5. Apply and verify the permanent fix.
6. Write a blameless post-mortem (RCA): what happened, why, how it was fixed, and prevention steps (tests, alerts, monitoring, runbooks).

function isValidParentheses(str) {
  var stack = [];
  var pairs = { ")": "(", "}": "{", "]": "[" };
  for (var i = 0; i < str.length; i++) {
    var ch = str[i];
    if (ch === "(" || ch === "{" || ch === "[") {
      stack.push(ch);
    } else {
      var top = stack.pop();
      if (top !== pairs[ch]) {
        return false;
      }
    }
  }
  return stack.length === 0;
}

function binarySearch(arr, target) {
  var low = 0;
  var high = arr.length - 1;
  while (low <= high) {
    var mid = Math.floor((low + high) / 2);
    if (arr[mid] === target) {
      return mid;
    } else if (arr[mid] < target) {
      low = mid + 1;
    } else {
      high = mid - 1;
    }
  }
  return -1;
}

        low = mid + 1; // keep searching right

function searchRotated(arr, target) {
  var low = 0, high = arr.length - 1;
  while (low <= high) {
    var mid = Math.floor((low + high) / 2);
    if (arr[mid] === target) return mid;
    if (arr[low] <= arr[mid]) { // left half is sorted
      if (target >= arr[low] && target < arr[mid]) {
        high = mid - 1;
      } else {
        low = mid + 1;
      }
    } else { // right half is sorted
      if (target > arr[mid] && target <= arr[high]) {
        low = mid + 1;
      } else {
        high = mid - 1;
      }
    }
  }
  return -1;
}

Q31. Detect a Cycle in a Linked List
function hasCycle(head) {

  while (fast !== null && fast.next !== null) {

Q33. Merge Two Sorted Linked Lists
function mergeSortedLists(l1, l2) {
  var dummy = new Node(0);
  var tail = dummy;
  while (l1 !== null && l2 !== null) {
    if (l1.value <= l2.value) {
      tail.next = l1;
      l1 = l1.next;
    } else {
      tail.next = l2;
      l2 = l2.next;
    }
    tail = tail.next;
  }
  tail.next = (l1 !== null) ? l1 : l2;
  return dummy.next;
}


Q34. Remove Nth Node From the End
function removeNthFromEnd(head, n) {
  var dummy = new Node(0);
  dummy.next = head;
  var fast = dummy;
  var slow = dummy;
  for (var i = 0; i < n; i++) {
    fast = fast.next;
  }
  while (fast.next !== null) {
    fast = fast.next;
    slow = slow.next;
  }
  slow.next = slow.next.next; // skip the target node
  return dummy.next;
}

Q37. Level Order (BFS) Traversal
function levelOrder(root) {
  var result = [];
  if (root === null) return result;
  var queue = [root];
  while (queue.length > 0) {
    var levelSize = queue.length;
    var currentLevel = [];
    for (var i = 0; i < levelSize; i++) {
      var node = queue.shift();
      currentLevel.push(node.value);
      if (node.left !== null) queue.push(node.left);
      if (node.right !== null) queue.push(node.right);
    }
    result.push(currentLevel);
  }
  return result;
}


Q38. Check if a Binary Tree is Balanced
function isBalanced(root) {
  function checkHeight(node) {
    if (node === null) return 0;
    var leftHeight = checkHeight(node.left);
    if (leftHeight === -1) return -1;
    var rightHeight = checkHeight(node.right);
    if (rightHeight === -1) return -1;
    if (Math.abs(leftHeight - rightHeight) > 1) return -1;
    return Math.max(leftHeight, rightHeight) + 1;
  }
  return checkHeight(root) !== -1;
}


Q39. Lowest Common Ancestor of Two Nodes
function lowestCommonAncestor(root, p, q) {
  if (root === null || root.value === p || root.value === q) {
    return root;
  }
  var left = lowestCommonAncestor(root.left, p, q);
  var right = lowestCommonAncestor(root.right, p, q);
  if (left !== null && right !== null) {
    return root; // p and q found in different subtrees
  }
  return (left !== null) ? left : right;
}

Q40. BFS Traversal of a Graph
function bfsTraversal(graph, start) {
  var visited = {};
  var queue = [start];
  var result = [];
  visited[start] = true;
  while (queue.length > 0) {
    var node = queue.shift();
    result.push(node);
    var neighbors = graph[node];
    for (var i = 0; i < neighbors.length; i++) {
      var neighbor = neighbors[i];
      if (!visited[neighbor]) {
        visited[neighbor] = true;
        queue.push(neighbor);
      }
    }
  }
  return result;
}
var graph40 = {0:[1,2], 1:[2], 2:[0,3], 3:[3]};
console.log(bfsTraversal(graph40, 2)); // [2, 0, 3, 1]


Q41. DFS Traversal of a Graph
function dfsTraversal(graph, start) {
  var visited = {};
  var result = [];
  function dfs(node) {
    visited[node] = true;
    result.push(node);
    var neighbors = graph[node];
    for (var i = 0; i < neighbors.length; i++) {
      if (!visited[neighbors[i]]) {
        dfs(neighbors[i]);
      }
    }
  }
  dfs(start);
  return result;
}

Q42. Detect a Cycle in an Undirected Graph
function hasCycleUndirected(n, edges) {
  var adjList = {};
  for (var i = 0; i < n; i++) adjList[i] = [];
  for (var i = 0; i < edges.length; i++) {
    adjList[edges[i][0]].push(edges[i][1]);
    adjList[edges[i][1]].push(edges[i][0]);
  }
  var visited = {};
  function dfs(node, parent) {
    visited[node] = true;
    var neighbors = adjList[node];
    for (var i = 0; i < neighbors.length; i++) {
      var neighbor = neighbors[i];
      if (!visited[neighbor]) {
        if (dfs(neighbor, node)) return true;
      } else if (neighbor !== parent) {
        return true; // visited and not parent -> cycle
      }
    }
    return false;
  }
  for (var node in adjList) {
    if (!visited[node]) {
      if (dfs(Number(node), -1)) return true;
    }
  }
  return false;
}
console.log(hasCycleUndirected(3, [[0,1],[1,2],[2,0]])); // true


Q43. Count Connected Components
function countComponents(n, edges) {
  var adjList = {};
  for (var i = 0; i < n; i++) adjList[i] = [];
  for (var i = 0; i < edges.length; i++) {
    adjList[edges[i][0]].push(edges[i][1]);
    adjList[edges[i][1]].push(edges[i][0]);
  }
  var visited = {};
  function dfs(node) {
    visited[node] = true;
    var neighbors = adjList[node];
    for (var i = 0; i < neighbors.length; i++) {
      if (!visited[neighbors[i]]) {
        dfs(neighbors[i]);
      }
    }
  }
  var count = 0;
  for (var node = 0; node < n; node++) {
    if (!visited[node]) {
      dfs(node);
      count++;
    }
  }
  return count;
}
console.log(countComponents(5, [[0,1],[1,2],[3,4]])); // 2

Q44. Bubble Sort
function bubbleSort(arr) {
  for (var i = 0; i < arr.length; i++) {
    for (var j = 0; j < arr.length - i - 1; j++) {
      if (arr[j] > arr[j + 1]) {
        var temp = arr[j];
        arr[j] = arr[j + 1];
        arr[j + 1] = temp;
      }
    }
  }
  return arr;
}
console.log(bubbleSort([5, 2, 9, 1, 6])); // [1, 2, 5, 6, 9]


Q45. Merge Sort
function mergeSort(arr) {
  if (arr.length <= 1) return arr;
  var mid = Math.floor(arr.length / 2);
  var left = mergeSort(arr.slice(0, mid));
  var right = mergeSort(arr.slice(mid));
  return merge(left, right);
}
function merge(left, right) {
  var result = [];
  var i = 0, j = 0;
  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) {
      result.push(left[i]);
      i++;
    } else {
      result.push(right[j]);
      j++;
    }
  }
  while (i < left.length) { result.push(left[i]); i++; }
  while (j < right.length) { result.push(right[j]); j++; }
  return result;
}
console.log(mergeSort([8, 3, 5, 1, 9, 2])); // [1, 2, 3, 5, 8, 9]


Q46. Quick Sort
function quickSort(arr) {
  if (arr.length <= 1) return arr;
  var pivot = arr[arr.length - 1];
  var left = [];
  var right = [];
  for (var i = 0; i < arr.length - 1; i++) {
    if (arr[i] < pivot) {
      left.push(arr[i]);
    } else {
      right.push(arr[i]);
    }
  }
  return quickSort(left).concat([pivot], quickSort(right));
}
console.log(quickSort([10, 7, 8, 9, 1, 5])); // [1, 5, 7, 8, 9, 10]

Q48. Climbing Stairs
function climbStairs(n) {
  if (n <= 2) return n;
  var dp = [];
  dp[1] = 1;
  dp[2] = 2;
  for (var i = 3; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }
  return dp[n];
}
console.log(climbStairs(4)); // 5


Q49. House Robber
function houseRobber(arr) {
  if (arr.length === 0) return 0;
  if (arr.length === 1) return arr[0];
  var dp = [];
  dp[0] = arr[0];
  dp[1] = Math.max(arr[0], arr[1]);
  for (var i = 2; i < arr.length; i++) {
    dp[i] = Math.max(dp[i - 1], dp[i - 2] + arr[i]);
  }
  return dp[arr.length - 1];
}
console.log(houseRobber([1, 2, 3, 1])); // 4


Q50. Longest Common Subsequence
function longestCommonSubsequence(str1, str2) {
  var m = str1.length;
  var n = str2.length;
  var dp = [];
  for (var i = 0; i <= m; i++) {
    dp.push(new Array(n + 1).fill(0));
  }
  for (var i = 1; i <= m; i++) {
    for (var j = 1; j <= n; j++) {
      if (str1[i - 1] === str2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1;
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
      }
    }
  }
  return dp[m][n];
}
console.log(longestCommonSubsequence("abcde", "ace")); // 3
